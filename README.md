# Машины GregTech New Horizons — Minecraft 1.7.10

Сайт про машины мода GregTech в сборке GT New Horizons 2.9, разложенные по ярусам
напряжения. Каждая постройка — трёхмерная модель из настоящих блоков мода: её
можно вертеть, перетаскивая мышкой, а блоки рядом с курсором раздвигаются и
показывают, из чего она сложена.

- **Язык сайта** задаёт начало адреса: `/ru` для русского, `/en` для английского.
  Адрес без языка перенаправляет на версию по языку браузера.
- **Главная** — иллюстрация со Звёздными вратами и два входа: «Машины» и «Калькулятор».
- **Раздел «Машины»** (`/ru/machines`) — паровой цех в 3D, лестница напряжений
  и вкладки эр. Вкладки видны только в разделе машин.
- **Страница яруса** (`/ru/tiers/steam`, `/ru/tiers/lv`) — карточки построек, а у
  пара ещё и одноблочные машины в бронзовой и стальной версии.
- **Страница машины** (`/ru/machines/<имя>`) — большая модель, рассказ, факты и
  схема состава с ползунком.
- **Калькулятор** (`/ru/calculator`) подбирает цепочку рецептов и по ней строит
  фабрику в 3D с машинами, трубами и питанием.

Ярусы описаны в `lib/tiers.ts`, машины — в `lib/machines.ts` (у каждой поле
`tier`). Чтобы добавить ярус MV, достаточно добавить его туда и раздать машины.

## Запуск

```bash
npm install
npm run calc-data
```

```bash
npm run dev
```

Откройте <http://localhost:3000/ru> или <http://localhost:3000/en>.
Команда `npm run calc-data` загружает рецепты и атлас значков в `public/calc`
из закреплённого коммита выгрузки GTNH 2.9 и проверяет контрольные суммы обоих файлов.

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | сборка |
| `npm run start` | запуск собранной версии |
| `npm test` | тесты (Vitest) |
| `npm run typecheck` | проверка типов |
| `npm run textures` | заново скачать и сконвертировать текстуры |
| `npm run calc-data` | скачать и проверить данные калькулятора |
| `npm run check-en` | найти русские строки в HTML английских страниц после сборки |

## Проверка перед выпуском

1. `npm run typecheck`.
2. `npm test`. Для тестов калькулятора нужна выгрузка из `npm run calc-data`.
3. `npm run build`, затем `npm run check-en`.
4. Остановите старый сервер на порту 3211, если он запущен. Выполните
   `npm run start -- -p 3211` и проверьте в браузере обе языковые версии и калькулятор.

## Как устроено

- **Next.js (App Router), React, TypeScript, Tailwind CSS v4.**
- **React Three Fiber + drei + @react-three/postprocessing** — сцена.
  Свечение, разъезд каналов, зерно и тональная компрессия — готовые эффекты,
  своих шейдеров нет.
- **Вращение** — готовый `OrbitControls` из drei (приближение и сдвиг выключены,
  колесо мышки остаётся прокрутке страницы).
- **Курсор** у каждой сцены свой (`PointerContext` в `lib/store.ts`): наведение
  на одну сцену не раздвигает блоки в другой. Кадр рисуется только когда курсор
  двигается, сцену вертят или блоки ещё не доехали до места.
- **zustand** хранит снимки карточек и то, какая карточка сейчас под мышкой
  (`lib/cards.ts`).

### Главное правило: все числа — в `lib/config.ts`

В компонентах, шейдере и схемах чисел нет. Каждое число в `lib/config.ts`
снабжено комментарием: почему именно столько и что сломается, если поставить
иначе. Правило проверяется тестом (`tests/rest.test.ts`, последний блок).

Исключения: 0, 1 и деление пополам в чистой арифметике, а также классы
Tailwind в разметке (`p-6`, `text-xs`) — это вёрстка, а не настройки сцены.

### Схемы не могут разойтись со сценой

Каждая схема на странице вызывает те же функции, что и сцена:

| Схема | Функция | Файл |
|---|---|---|
| Разбор постройки по блокам | `explodedPosition()` | `lib/structure.ts` |
| Калькулятор нагрева | `heatCapacity()`, `heatBonuses()` | `lib/heat.ts` |

### Как добавить постройку

Все постройки описаны в `lib/machines.ts`. Схема (`layers`) записывается так
же, как в исходниках мода с `transpose(...)`: слои сверху вниз, строки от
фасада назад, символы слева направо; пробел — пусто, `~` — контроллер.
Если в исходнике схема без `transpose` (срезы от фасада назад), её нужно
переложить в слои — так сделано для дробилки и компрессора.

Куда какой блок раздвигается, считается само (`lib/structure.ts`): блок
уходит от оси постройки и вверх, но только туда, где свободно, — поэтому
раздвинутые блоки никогда не въезжают друг в друга. Это проверяется тестом
для каждой постройки.

### Откуда сведения о моде

Схемы построек, ярусы напряжения и формулы нагрева взяты из исходного кода
[GT5-Unofficial](https://github.com/GTNewHorizons/GT5-Unofficial): у каждой
машины на её странице есть ссылка на свой файл. Сведения об электрической
печи сверены с [вики GT New Horizons](https://wiki.gtnewhorizons.com/wiki/Electric_Blast_Furnace).
Код взят с ветки, на которой сейчас идёт 2.10; паровая эра там устроена так же,
как в 2.9.

## Карточки машин

В покое карточка — картинка, снятая с трёхмерной модели один раз при загрузке
(невидимый холст за краем окна, `components/cards/CardStage.tsx`). Под мышкой
поверх неё ложится живая модель на одном общем холсте. Этот холст — часть
страницы, а не прибит к окну, поэтому при прокрутке он едет вместе с карточкой
и не отстаёт от неё.

## Замеры

Сервер разработки примерно вдвое медленнее сборки — мерить нужно только
собранную версию: `npm run build`, `npm run start`, затем открыть страницу с
`?bench` в адресе и нажать «Замерить кадр». Части картинки выключаются через
`&off=bloom`, `&off=chromatic`, `&off=shadows` или `&off=all`; ещё две ручки —
`&msaa=0` и `&dpr=0.7`. На самом сайте замеры не показываются.
