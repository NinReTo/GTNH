# Electric Blast Furnace — GregTech, Minecraft 1.7.10

Одностраничный сайт про электрическую доменную печь (EBF) из мода GregTech.
Наверху — трёхмерная печь из настоящих блоков мода. Её можно вертеть,
перетаскивая мышкой, а блоки рядом с курсором раздвигаются и показывают
светящееся нутро. Ниже — страница с работающими схемами: из чего печь
сложена, как считается нагрев, как устроена прокрутка.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Откройте <http://localhost:3000>.

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | сборка |
| `npm run start` | запуск собранной версии |
| `npm test` | тесты (Vitest) |
| `npm run typecheck` | проверка типов |
| `npm run textures` | заново скачать и сконвертировать текстуры |

## Как устроено

- **Next.js (App Router), React, TypeScript, Tailwind CSS v4.**
- **React Three Fiber + drei + @react-three/postprocessing** — сцена.
  Свечение, разъезд каналов, зерно и тональная компрессия — готовые эффекты.
  Самописный шейдер один: переход сцены в страницу
  (`components/scene/TransitionEffect.ts`).
- **Вращение** — готовый `OrbitControls` из drei (приближение и сдвиг выключены,
  колесо мышки остаётся прокрутке страницы).
- **zustand** хранит два значения: положение прокрутки (ведёт переход к странице)
  и положение курсора над холстом (раздвигает блоки). Кадр рисуется только когда
  что-то из этого меняется или блоки ещё не доехали до места.

### Главное правило: все числа — в `lib/config.ts`

В компонентах, шейдере и схемах чисел нет. Каждое число в `lib/config.ts`
снабжено комментарием: почему именно столько и что сломается, если поставить
иначе. Правило проверяется тестом (`tests/rest.test.ts`, последний блок).

Исключения: 0, 1 и деление пополам в чистой арифметике, а также классы
Tailwind в разметке (`p-6`, `text-xs`) — это вёрстка, а не настройки сцены.

### Схемы не могут разойтись со сценой

Каждая схема на странице вызывает те же функции, что и сцена:

| Схема | Функция | Файл |
|---|---|---|
| Разбор печи по блокам | `explodedPosition()` | `lib/ebf.ts` |
| Фазы прокрутки | `phaseThresholds()` | `lib/scroll.ts` |
| Калькулятор нагрева | `heatCapacity()`, `heatBonuses()` | `lib/heat.ts` |

### Откуда сведения о моде

Структура печи, ярусы напряжения и формулы нагрева взяты из исходного кода
[GT5-Unofficial](https://github.com/GTNewHorizons/GT5-Unofficial)
(`MTEElectricBlastFurnace.java`, `HeatingCoilLevel.java`,
`OverclockCalculator.java`, `GTValues.java`) и сверены с
[вики GT New Horizons](https://wiki.gtnewhorizons.com/wiki/Electric_Blast_Furnace).
Форма печи в `lib/ebf.ts` записана теми же строками, что и в исходнике мода.

## Как повторить замеры

Сервер разработки примерно вдвое медленнее сборки — мерить нужно только
собранную версию.

```bash
npm run build
```

```bash
npm run start
```

1. Откройте <http://localhost:3000/?bench>.
2. Нажмите «Замерить кадр» несколько раз — возьмите среднее значение.
3. Повторите с выключенными по одному частями: `?bench&off=bloom`,
   `?bench&off=chromatic`, `?bench&off=transition`, `?bench&off=shadows`,
   и со всем выключенным: `?bench&off=all`.
4. Внесите результаты в `PERF.measured` в `lib/config.ts` — график на странице
   строится из них.

Кнопка рисует 120 кадров подряд и после каждого читает один пиксель: это
заставляет видеокарту действительно закончить кадр. Тени при этом
перерисовываются на каждом кадре — меряется худший случай, когда блоки
двигаются. Ещё две ручки для опытов: `&msaa=0` (сглаживание) и `&dpr=0.7`
(плотность пикселей).
